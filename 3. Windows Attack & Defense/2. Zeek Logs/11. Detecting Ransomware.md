## Description

`Ransomware` leverage an array of techniques to accomplish their goals. There are mainly two methods:

1. `File Overwrite Approach`: Ransomware employs this tactic by accessing files through the SMB protocol, encrypting them, and then directly overwriting the original files with their encrypted versions (again through the SMB protocol).
->  To detect this approach, security teams should look for excessive file overwrite operations on the system.

![](../Image/Pasted%20image%2020251007155005.png)

2. `File Renaming Approach`: In this approach, ransomware actors use the SMB protocol to read files, they then encrypt them and they finally rename the encrypted files by appending a unique extension (again through the SMB protocol).
-> Detection involves monitoring for an unusual number of files being renamed with the same extension, particularly those associated with known ransomware variants.

![](../Image/Pasted%20image%2020251007161125.png)

```ad-note
**File Overwrite Approach**
Original: report.docx
→ Ransomware mở file report.docx (write mode)
→ Ghi đè nội dung bằng dữ liệu mã hóa (thay thế toàn bộ)

**File Renaming Approach**
Original: report.docx
→ Ransomware đọc report.docx → tạo bản mã hóa: report.docx.tmp
→ Xóa report.docx (gốc)
→ Đổi tên report.docx.tmp → report.docx.lockbit
```

## Detecting Ransomware With Splunk & Zeek Logs 

#### Excessive Overwriting

```shell
index="ransomware_open_rename_sodinokibi" sourcetype="bro:smb_files:json" 
| where action IN ("SMB::FILE_OPEN", "SMB::FILE_RENAME")
| bin _time span=5m
| stats count by _time, source, action
| where count>30 
| stats sum(count) as count values(action) dc(action) as uniq_actions by _time, source
| where uniq_actions==2 AND count>100
```

![](../Image/Pasted%20image%2020251007164438.png)

#### Excessive Renaming With The Same Extension

```shell
index="ransomware_new_file_extension_ctbl_ocker" sourcetype="bro:smb_files:json" action="SMB::FILE_RENAME" 
| bin _time span=5m
| rex field="name" "\.(?<new_file_name_extension>[^\.]*$)"
| rex field="prev_name" "\.(?<old_file_name_extension>[^\.]*$)"
| stats count by _time, id.orig_h, id.resp_p, name, source, old_file_name_extension, new_file_name_extension,
| where new_file_name_extension!=old_file_name_extension
| stats count by _time, id.orig_h, id.resp_p, source, new_file_name_extension
| where count>20
| sort -count
```

## Q & A

 Modify the action-related part of the Splunk search of this section that detects excessive file overwrites so that it detects ransomware that delete the original files instead of overwriting them. Run this search against the `"ransomware_excessive_delete_aleta"` index and the `"bro:smb_files:json"` sourcetype. Enter the value of the "count" field as your answer.

Answer: 

```shell
index="ransomware_excessive_delete_aleta" sourcetype="bro:smb_files:json"
| where action IN ("SMB::FILE_OPEN", "SMB::FILE_DELETE")
| bin _time span=5m
| stats count by _time, source, action
| where count>30
| stats sum(count) as count values(action) dc(action) as uniq_actions by _time, source
| where uniq_actions==2 AND count>100
```
